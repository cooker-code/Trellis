# Research: remaining Python i18n surface

- **Query**: Inspect the Python i18n framework and remaining user-facing Python strings for i18n PR3.
- **Scope**: `packages/cli/src/templates/trellis/scripts/**`, related specs, and tests
- **Date**: 2026-07-27

## Existing framework

PR1-A already ships:

- `common/i18n.py`: `set_locale`, `get_locale`, `t`, English fallback, key fallback, lazy bundle loading.
- `common/i18n_strings/en.py` and `zh.py`.
- `common/config.py:get_language()` with `en|zh` validation.
- `init_developer.py` as the only migrated caller.

Current English and Chinese bundles contain only five `init_developer.*` keys. There are no direct tests of Python `t()` or bundle parity.

GitNexus reports LOW impact for `common/i18n.py:t` (one current direct caller, `init_developer.main`), but PR3 intentionally expands that caller set across core scripts.

## Scope classification

### Translate through `t(key)`

- User-visible success, warning, error, hint, and status prose.
- Argparse command descriptions and `help=` text.
- Multi-line usage prose while preserving commands/flags/placeholders.
- Text-mode session/package context headings and explanatory prose.
- Safe-commit warnings, including the existing literal negative example `git add -f .trellis/`.
- Visible errors raised by core entry paths.

Every core entry point must call `set_locale()` once before constructing argparse or emitting output. Shared functions should call `t()` but should not independently re-resolve locale.

### Preserve as stable protocol/technical output

Do not translate:

- command names and flags;
- paths, environment variables, JSON/JSONL keys, status enum values, package/task IDs, branch names, and placeholders;
- `task.py create`/`archive` raw stdout paths used by callers;
- `task.py current` raw path output;
- the `task.py current --source` labels `Current task:`, `Source:`, and `State: stale`, because bundled and platform agent preludes explicitly tell agents to parse/read the `Current task:` line;
- JSON-mode keys or values that are identifiers;
- stdout/stderr routing and exit codes;
- `[OK]`, `[WARN]`, `[ERROR]` labels where they serve as stable log severity tokens.

A Chinese locale may translate the prose around these tokens, but the tokens and machine-consumed labels remain stable.

### Do not translate in this PR

- Python comments and developer-only docstrings.
- Debug-only diagnostics and assertions.
- `if __name__ == "__main__"` self-test output in library-only modules such as `paths.py` and `task_utils.py`.
- Persisted journal/index Markdown schemas generated by `developer.py` and `add_session.py`; these contain English markers/headers parsed by existing update logic and are not console messages. Localizing workspace artifacts needs a separate source-template/schema design.
- Platform-specific Python hook templates outside `templates/trellis/scripts/**`.
- The optional `scripts/hooks/linear_sync.py` integration. It executes from a nested directory and cannot import `common.i18n` without changing its execution/import contract or adding forbidden `sys.path` manipulation. Track this as a documented roadmap remainder rather than duplicating locale logic.
- The invalid-`language` bootstrap warning in `common/config.py:get_language()`: locale is not valid/resolved at that point, and `i18n.py` imports `config.py`. Keep the English fallback diagnostic to avoid a circular bootstrap dependency.

These exclusions must be documented in the localization coverage page so “remaining Python messages” has a verifiable boundary.

## Message-key design

Follow `.trellis/spec/cli/backend/script-conventions.md`:

- Flat keys named `<module_or_command>.<short_action>`.
- English bundle is authoritative.
- Chinese bundle mirrors keys at PR completion.
- Preserve identical `str.format` placeholder names in both locales.
- Missing Chinese key falls back to English; missing both falls back to the key.

Suggested namespaces:

- `task.*`, `task_create.*`, `task_archive.*`, `task_context.*`
- `add_session.*`
- `developer.*`, `get_developer.*`
- `context.*`, `packages_context.*`
- `safe_commit.*`
- `config.*`

Avoid one key per punctuation-only/blank line. Keep formatting in callers when it is not language-dependent, and use one key for a cohesive multi-line block when that block is always emitted together.

## Drift and validation gaps

`packages/cli/scripts/check-i18n-drift.js` currently checks suffix-file git timestamps only. The script-conventions spec claims Python bundle key comparison, but that check does not exist. PR3 should add:

1. English/Chinese key-set comparison.
2. Placeholder-set comparison per shared key.
3. Warning output in normal mode and non-zero behavior under `--strict`.
4. Compound template recognition for `*.zh.md.txt`.

## Required tests

Create a dedicated Python-i18n subprocess/integration test rather than only source-string assertions:

1. Copy `getAllScripts()` into a temporary `.trellis/scripts` tree.
2. Run with no locale/config and assert representative English output.
3. Run with `TRELLIS_LANGUAGE=zh` and assert representative Chinese output for `task.py`, `add_session.py`, `get_developer.py`, and `get_context.py` text mode.
4. Verify config-based `language: zh` when the environment override is absent.
5. Verify `TRELLIS_LANGUAGE` wins over config.
6. Verify missing Chinese key falls back to English and missing-both returns the key.
7. Verify English/Chinese placeholder names are equal.
8. Verify `task.py current --source` remains protocol-stable under `zh`.
9. Verify JSON mode keeps the same schema in `en` and `zh`.
10. Verify exit codes and stdout/stderr channels are unchanged.
11. Run the same locale sequence in one process where practical to catch module-state leakage.

Use the platform-selected Python command in tests, preserve Python 3.9 compatibility (`from __future__ import annotations`), and run `pnpm lint:py`.

## Design constraints

- Do not add gettext/Babel or any dependency; templates remain stdlib-only.
- Do not add a second locale resolver or parser. PR3 consumes the PR1/PR2 locale contract.
- Avoid importing `i18n` from `config.py` at module import time because `i18n.py` already imports config accessors.
- Preserve Windows UTF-8 behavior from `common/__init__.py`.
- Keep entry modules simple: resolve locale once, then delegate.

## Impact summary

GitNexus reports LOW risk for the current entry-point symbols (`task.py:main`, `add_session.py:main`, and `git_context.py:main`). Practical risk is output-contract compatibility, not call-graph depth. Tests must focus on exact channels, exit codes, parser labels, and JSON schemas.
