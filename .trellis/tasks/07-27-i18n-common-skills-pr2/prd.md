# i18n PR2: Chinese common commands, single-file skills, and Trellis agents

## Goal

Complete the second Chinese-localization content slice by making common commands, common single-file workflow skills, and every generated Trellis research/implement/check agent definition locale-aware across all supported platforms.

Users selecting `zh` receive Chinese human/LLM-facing prose at the existing unsuffixed platform paths. English remains the default, missing translations fall back per file/key to English, and init/update/hash behavior remains byte-stable and locale-transparent.

## Dependencies

1. PR1-A's locale contract remains authoritative: `--language` > `TRELLIS_LANGUAGE` > `.trellis/config.yaml` > `en`.
2. PR1-B should land first when it changes shared drift-checker/tests. PR2 must rebase on and extend that checker rather than replacing it.
3. PR2 must expose a reusable explicit locale-selection/propagation contract for PR3. PR3 must not introduce a second locale resolver.

## Requirements

### R1. Source organization and translation policy

- Keep all existing English command, skill, and agent source files unchanged.
- Add Chinese siblings beside English sources:
  - common Markdown: `foo.md` + `foo.zh.md`;
  - Markdown agents/droids: `foo.md` + `foo.zh.md`;
  - Codex agents: `foo.toml` + `foo.zh.toml`;
  - Kiro agents: `foo.json` + `foo.zh.json`.
- Treat English sources as the canonical logical file set. Orphan translations never become output.
- Translate all human/LLM-facing headings, prose, descriptions, checklists, tables, examples, report-format prose, and Markdown/HTML comments.
- Preserve proper names and technical identifiers, including Trellis, GitNexus, ABCoder, platform names, role IDs, commands, flags, paths, filenames, environment variables, placeholders, JSON/JSONL/YAML/TOML keys, status values, event/tool/permission names, code identifiers, code-fence languages, and link targets.
- Preserve stable protocol tokens such as `Active task:`, `{TASK_DIR}`, `<!-- trellis-hook-injected -->`, `implement.jsonl`, and `check.jsonl` when code/tests consume them literally.

### R2. Common command and single-file skill selection

- Localize all current common command and single-file skill sources. The current planning baseline is 3 command files and 5 skill files; tests derive the set dynamically.
- `getCommandTemplates(language)` and `getSkillTemplates(language)` select Chinese siblings under `zh` and fall back per file to English.
- Returned logical names remain unchanged and never contain `.zh`.
- Cache selected results by locale so `en -> zh -> en` within one process returns correct bytes each time.
- Preserve existing command-capability filtering: `start` remains absent on agent-capable platforms except Codex's existing special `trellis-start` skill, and remains present on agent-less platforms.
- Keep platform placeholder rendering and neutral `.agents/skills/` rendering behavior unchanged.

### R3. Generated common prose

- Localize generated skill matcher descriptions and Qoder command-palette descriptions through parallel English/Chinese template metadata sources with per-key English fallback.
- Localize the generated pull-based agent prelude through parallel English/Chinese template sources.
- Thread locale through prelude injection for Codex, Gemini, Qoder, Copilot, and Pi implement/check outputs.
- Preserve exact English generated bytes when `language=en`.

### R4. Trellis agent coverage

- Localize the three physical agent sources for each of: Claude Code, Cursor, OpenCode, Codex, Kiro, Gemini CLI, Qoder, CodeBuddy, Factory Droid, and Pi Agent.
- GitHub Copilot continues deriving its three generated agents from Cursor sources; it must receive the selected locale before Copilot tool-frontmatter normalization and pull-prelude injection. Do not create a duplicate Copilot agent source tree.
- Preserve every platform's format contract:
  - Cursor description stays single-line;
  - Gemini omits `tools:`;
  - OpenCode keeps `mode: subagent` and permission map;
  - Codex keeps TOML keys/triple-quoted instructions/sandbox mode;
  - Kiro remains valid JSON with identical schema/tools/hooks;
  - Copilot keeps normalized YAML tool-list vocabulary;
  - Pi remains extension-backed and installs no Python hooks.
- Preserve agent responsibilities, recursion guards, context-loading behavior, research persistence, write restrictions, and forbidden git operations. Translation must not redesign agent semantics.

### R5. Explicit locale propagation

- Resolve locale once at init/update boundaries and pass it explicitly through platform configure/collect and common/agent resolver calls.
- The full-init path and existing-project add-platform/re-init fast path must use the same selected locale.
- `collectPlatformTemplates(platform, language)` must produce update bytes for the same locale used by init.
- Do not add a process-global locale cache or make individual platform loaders independently reread config.
- Leave a reusable English-canonical, suffix-aware selector that PR3 can use for recursive Markdown and compound `.md.txt` sources.

### R6. Destination, fallback, and hash behavior

- Translation sources always land under existing unsuffixed command/skill/agent paths.
- Missing translation of a body, description, prelude, or individual metadata key falls back to English without failing init/update.
- English and Chinese output maps have identical destination path sets.
- No generated file path or `.template-hashes.json` key contains `.zh.`.
- Hash keys remain landed paths and values remain hashes of landed bytes; no hash schema or migration change.
- Existing user-modification conflict behavior remains intact when switching locale.

### R7. Drift and structural validation

- Extend i18n source discovery to include PR2's `.zh.md`, `.zh.toml`, and `.zh.json` sources while preserving PR1-B workflow checks.
- Dynamically verify every PR2-covered English source has a Chinese sibling and every translation has an English counterpart.
- Validate protected placeholders/tokens and platform-specific structures rather than requiring translated prose to match English.
- Drift checking remains warning-only by default and fails under `--strict`.

### R8. Init/update/build verification

- For every platform and both locales, configured files must match `collectPlatformTemplates()` byte-for-byte.
- Codex and Gemini must produce byte-identical overlapping `.agents/skills/` files under `zh` as well as `en`.
- Chinese first init, existing-project add-platform, same-locale no-op update, English-to-Chinese update, and Chinese-to-English update must be covered.
- Build/package smoke must prove locale sidecars ship in `dist`/npm while generated user projects contain only unsuffixed paths.

## Constraints

- Do not modify English source prose solely to support translation.
- Do not change workflow semantics, agent responsibilities, platform capabilities, command names, or invocation syntax.
- Do not add runtime machine translation, gettext/Babel, a YAML dependency, or a new locale resolver.
- Do not localize TypeScript CLI help/prompts/errors/output.
- Do not start implementation until `prd.md`, `design.md`, `implement.md`, and context manifests are reviewed.

## Out of scope

- PR1-B `workflow.zh.md`, workflow parser compatibility, and workflow-specific structural grammar.
- PR3 bundled skills/references, blank spec templates, Python user messages, and Beta docs.
- Platform hook/settings/extension/plugin prose not derived from PR2 common/agent sources.
- Marketplace content, docs-site, Release docs, and languages other than English/Chinese.
- Refactoring duplicated platform agent bodies into a new cross-platform agent DSL.
- Renaming proper names or shipped technical identifiers.

## Acceptance criteria

- [ ] Every current English common command and single-file skill has a Chinese sibling; `zh` resolution returns Chinese content under unchanged logical names.
- [ ] Every physical English Trellis agent source across the 10 source-owning platforms has a Chinese sibling in the correct Markdown/TOML/JSON format.
- [ ] All 11 agent-capable platforms generate Chinese research/implement/check definitions at their existing target paths; Copilot derives Chinese output from Cursor without a duplicate source tree.
- [ ] Missing body/description/prelude/key translations fall back to English without failure or extra output paths.
- [ ] `en -> zh -> en` in one process returns correct locale bytes without cache contamination.
- [ ] English and Chinese platform maps have identical key sets and no key contains `.zh.`.
- [ ] Every platform's init writer and update collector produce byte-identical content for each locale.
- [ ] English generated output remains byte-compatible with pre-PR2 behavior.
- [ ] Generated Chinese skill/Qoder descriptions and pull-based preludes are Chinese while stable technical tokens remain unchanged.
- [ ] Cursor, Gemini, OpenCode, Codex, Kiro, Copilot, Pi, recursion-guard, context-loading, and research-persistence format contracts remain valid.
- [ ] Codex/Gemini overlapping `.agents/skills/` content is byte-identical under both locales.
- [ ] Fresh `zh` init and existing-project `zh` add-platform paths land representative Chinese command/skill/agent files and unsuffixed hash keys.
- [ ] Pristine English-to-Chinese and Chinese-to-English update switches refresh bytes/hashes at unchanged paths and are idempotent on rerun.
- [ ] User-modified translated files continue through existing conflict protection rather than being silently overwritten.
- [ ] `pnpm run i18n:check`, lint, typecheck, focused tests, full tests, build, npm pack inspection, and built-binary smoke pass.
