## Draft: `design.md`

```markdown
# Design: locale-aware common templates and cross-platform Trellis agents

## 1. Context

PR1-A resolves `en|zh` and selects `workflow.md`, but common command/skill getters and platform agent loaders remain locale-blind. Naively adding sidecars would create extra logical commands/agents because current filesystem scanners accept every `.md`, `.toml`, or `.json`.

PR2 adds source-layer selection and threads one resolved locale through the platform rendering graph. Downstream destination assembly, hash tracking, migrations, uninstall, and platform invocation remain locale-blind.

## 2. Design goals

1. One English-canonical selector for common/agent sources.
2. Explicit locale propagation from init/update into configure/collect.
3. Per-file/key English fallback and unsuffixed destinations.
4. Full generated-prose localization, including frontmatter descriptions and pull preludes.
5. Exact English compatibility and init/update byte parity.
6. A stable selector/propagation API that PR3 can reuse.

## 3. Non-goals

- Workflow, bundled-skill, spec-template, Python-message, docs-site, or TypeScript CLI localization.
- Agent semantic redesign or deduplication.
- Hash schema/migration changes.

## 4. Source-selection primitive

Add a pure suffix-aware selector in `templates/template-utils.ts`.

```ts
interface LocalizedTemplateSelection {
  logicalFile: string;
  sourceFile: string;
}

selectLocalizedTemplateFiles(
  files: readonly string[],
  semanticSuffix: string,
  language: SupportedLanguage,
): LocalizedTemplateSelection[]
```

Algorithm:

1. Identify canonical English files ending in `semanticSuffix` while excluding recognized locale sidecars.
2. For each canonical file, derive `<stem>.<language><semanticSuffix>`.
3. Select it when present and `language != en`; otherwise select English.
4. Return canonical logical filenames in deterministic order.
5. Ignore orphan translations.

The explicit semantic suffix supports `.md`, `.toml`, `.json`, and PR3's `.md.txt` without `path.extname()` mistakes.

`createTemplateReader()` exposes `listMdAgents(language)`, `listJsonAgents(language)`, and `listTomlAgents(language)` through this primitive. Claude/Codex hand-written readers and OpenCode's recursive walker must use the same primitive rather than duplicate selection rules.

## 5. Locale propagation

Use explicit arguments, defaulting public low-level APIs to English for compatibility:

```text
init resolved language
  -> handleReinit(..., language)
  -> configurePlatform(platform, cwd, language)
     -> configureX(cwd, language)
        -> common resolvers + agent getters

update collectTemplateFiles resolved language
  -> collectPlatformTemplates(platform, language)
     -> collector common resolvers + agent getters
```

`PlatformFunctions.configure` and `collectTemplates` receive language. `configurePlatform` may default to `resolveLanguage(cwd)`; `collectPlatformTemplates` defaults to `en` for manifest key-only callers/tests, while update always passes its resolved value.

Do not place locale in module-global state. Any selected-content cache is keyed by the explicit locale.

## 6. Common command/skill model

`getCommandTemplates(language)` and `getSkillTemplates(language)` use locale-keyed caches and return unchanged logical names.

Extract generated descriptions from TypeScript dictionaries into parallel template metadata:

```text
common/descriptions.json
common/descriptions.zh.json
```

The English file contains current descriptions exactly. Chinese values overlay by key; missing file/key falls back to English. Resolved templates carry the selected description into wrapping helpers. This keeps translation prose in parallel source files and makes English output testable.

All command/skill resolver variants receive `language`:

- `resolveCommands`
- `resolveSkills`
- `resolveSkillsNeutral`
- `resolveAllAsSkills`
- `resolveAllAsSkillsNeutral`
- `resolveCodexTrellisStartSkill`

Capability filtering and placeholder semantics remain unchanged.

## 7. Pull-based prelude model

Extract the current inline English prelude without changing its rendered bytes:

```text
common/agent-preludes/pull-based.md
common/agent-preludes/pull-based.zh.md
```

The source includes a protected JSONL-role placeholder. `buildPullBasedPrelude(agentType, language)` selects locale, substitutes `implement.jsonl`/`check.jsonl`, and applies Python command adaptation.

Thread locale through Markdown/TOML prelude injection/apply helpers. Research remains unaffected by the existing prelude-selection logic; PR2 does not change that semantic contract.

## 8. Agent source and platform transformations

English files define the output role set. Chinese siblings only replace prose content.

- Claude: make recursive init copying use canonical/selected agents or replace agent copying with the same selected getter used by update.
- Cursor/CodeBuddy/Gemini/Qoder/Droid/Pi: locale-aware shared readers.
- OpenCode: locale overlay within the shared init/update walker; skip sidecar paths.
- Codex: locale-aware TOML reader before pull-prelude insertion.
- Kiro: locale-aware JSON reader before `{{PYTHON_CMD}}` resolution.
- Copilot: call Cursor getter with locale, normalize tools, then inject selected prelude.

All existing post-selection transforms run in the same order in init and update.

## 9. Data-flow and hash contract

```text
English canonical source set
  -> locale overlay / English fallback
  -> platform placeholder + wrapper/prelude transformations
  -> existing unsuffixed destination map
  -> write/init or compare/update
  -> hash landed bytes under destination key
```

Locale suffixes never reach `writeAgents`, `writeSkills`, platform maps, manifests, or uninstall. Switching locale is an ordinary template-content update protected by stored hashes.

## 10. Validation model

### Structural parity

Compare protected structure, not prose:

- placeholder/token sets;
- role/file IDs;
- frontmatter keys and stable values;
- JSON schema/tools/hooks;
- TOML stable assignments/triple-quote balance;
- code-fence sequence and technical literals;
- link targets.

### Behavioral parity

- en/zh destination key-set equality;
- every platform configure-vs-collect byte equality;
- English generated bytes unchanged;
- Codex/Gemini shared path byte equality;
- first init/reinit/update/fallback/cache behavior.

## 11. Compatibility

- No/`en` language selects current English sources and exact current generated bytes.
- Missing translation silently degrades to English.
- Existing user-modified files remain conflict-protected.
- Platform agent schemas and command invocation paths do not change.
- Build packages both source locales, but user projects receive one selected unsuffixed output.

## 12. PR boundaries

PR1-B owns workflow translation/parsing/checker grammar. PR2 rebases on it and only extends generic source families. PR3 consumes PR2's selector and locale propagation for bundled/spec sources. Shared files (`check-i18n-drift.js`, common/shared configurators, init/update/regression tests) are serialized in that order.

## 13. Rollback

- Removing a Chinese sidecar automatically falls back to English.
- Reverting locale propagation restores English-only behavior without data migration.
- Metadata/prelude extraction can be reverted as one unit because English generated bytes are unchanged.
- No user content or persisted schema requires migration.

## 14. Risks and mitigations

| Risk | Mitigation |
|---|---|
| Sidecar emitted as extra command/agent | English-canonical selector + path-set tests |
| Init/update choose different locale | Explicit language argument + all-platform byte-parity test |
| Cache poisoned by first locale | Locale-keyed caches + en/zh/en regression |
| Mixed-language generated output | Localized description/prelude sources |
| Claude/OpenCode recursive leaks | Dedicated no-sidecar integration assertions |
| Copilot omitted | Cursor-derived locale test after normalization/prelude |
| Shared `.agents/skills` collision | Neutral renderer parity under both locales |
| Structured translation invalid | JSON/TOML/platform structural tests |
| PR overlap conflict | PR1-B -> PR2 -> PR3 serialized shared-file ownership |
```
