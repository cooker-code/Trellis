交互式架构导览

Trellis 到底是怎么工作的？

它不是一个常驻 AI 服务。它先用 TypeScript CLI 把工作流安装进项目，再由项目内的 Python、JS、Markdown 和平台 hooks，在正确时机把 task、spec、workflow 与 journal 交给 AI。

纯 CSS / 原生 HTML 交互，不依赖 JavaScript
1
一句话心智模型：CLI 负责“安装和升级”，生成到项目里的文件负责“每天运行”。Trellis 的长期记忆在 Git 可见文件里，不在模型的临时聊天记忆里。

先分清三个角色

读源码时始终问：我看到的是模具、生成器，还是已经落地的运行时？

源模板源

packages/cli/src/templates/ 是权威模具。维护 Trellis 本身通常从这里改。

编译器Configurator（配置器）

把通用 workflow（工作流）语义编译为 Claude、Cursor、Codex、Pi 等平台格式。

安装器TypeScript CLI（命令行工具）

init 首次生成，update 安全同步，uninstall 按所有权删除。

运行时项目文件

.trellis/、平台 hooks（钩子）、skills（技能）、agents（代理）是每天真正运行的部分。

消费者AI 会话

AI 最终看到当前任务、阶段提醒、相关规范和可用工具，而不必理解模板系统。

文件运行时：五种记忆，五种生命周期

点击每个文件节点展开。Trellis 不是把所有东西混成一个大 prompt。

流程workflow.md

回答“现在按什么流程做”，包含阶段、门禁、平台路由和 breadcrumb（面包屑）。

任务tasks/<task>

回答“这次做什么”，包含 task.json、PRD、设计、计划与 JSONL context（上下文）。

契约spec/

回答“以后这类代码必须怎么写”，保存长期工程契约。

记忆workspace/

回答“以前发生过什么”，保存 developer（开发者）journal（日志）与索引。

会话.runtime/

回答“这个窗口正在做什么”，按 session key（会话键）隔离 active task（活动任务）。

S
Session 隔离：active_task.py 从平台 session/conversation/transcript id 或 TRELLIS_CONTEXT_ID 得到 key，写入 .trellis/.runtime/sessions/<key>.json。两个窗口因此可处理不同任务。

packages/core：可复用 TypeScript SDK

它和项目内 Python runtime 有交集，但不是同一个层次。展开查看三个公开子包。

通道事件驱动协作

events.jsonl 是真相源，提供 channel（通道）、thread（线程）、worker（工作者）、watch（监听）、interrupt（中断）API（应用程序接口）。

TASKTask 共享契约

定义 canonical task record、目录校验、读写与 phase 推导，镜像 Python task.json。

MEM本地会话检索

读取 Claude、Codex 等本地会话，提供 list、search、context 与 dialogue extract。

45 分钟源码阅读路线

不要从 2000 行的 init.ts 第一行读到最后。按“生成 → 运行 → 更新”闭环追一遍。

  1. 5 分钟：命令入口

    packages/cli/src/cli/index.ts，看命令和 flags 如何进入实现。

  2. 7 分钟：生成骨架

    configurators/workflow.ts，看 .trellis 如何落地。

  3. 7 分钟：平台编译

    types/ai-tools.ts → configurators/index.ts → 任一平台 configurator。

  4. 8 分钟：Task runtime

    templates/trellis/scripts/task.py 与 common/active_task.py。

  5. 8 分钟：Context 注入

    shared-hooks/session-start.py、inject-workflow-state.py、inject-subagent-context.py。

  6. 10 分钟：安全升级

    commands/update.ts 的 collect/analyze + utils/template-hash.ts。

最短主调用链

cli/index.ts → commands/init.ts → configurators/workflow.ts + configurePlatform() → templates/* → 用户项目 hooks → get_context.py / task.py

为什么 TypeScript + Python 并存？

TypeScript 负责 npm CLI、模板编译和 SDK；Python 标准库脚本随项目复制即可运行，不要求用户项目安装额外包。

仓库里有 sync 命令吗？

当前没有独立 trellis sync。首次安装是 init，后续同步模板是 update。

核心结论：Trellis 不是“更多 prompt”，而是把流程、任务、规范和记忆变成可版本化文件，再通过平台适配层按需注入 AI。
